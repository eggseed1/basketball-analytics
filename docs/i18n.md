# Internationalization (next-intl)

UI locales without URL prefixes. Locale comes from the `DRBL_LOCALE` cookie or
`Accept-Language`. URLs stay identical across languages.

## Supported locales

| Code | Native name | Catalog |
|------|-------------|---------|
| `en` | English | `messages/en.json` (source of truth) |
| `es` | Español | `messages/es.json` |
| `fr` | Français | `messages/fr.json` |
| `de` | Deutsch | `messages/de.json` |
| `pt-BR` | Português (Brasil) | `messages/pt-BR.json` |
| `ko` | 한국어 | `messages/ko.json` |
| `ja` | 日本語 | `messages/ja.json` |
| `zh-Hans` | 简体中文 | `messages/zh-Hans.json` |
| `zh-Hant` | 繁體中文 | `messages/zh-Hant.json` |
| `en-XA` | Pseudolocale (dev only) | `messages/en-XA.json` |

Translation status: **machine-assisted** (catalog fill Oct 2026 for Compare,
Sentiment, Movement, Acquisitions, Offseason, Injuries, History, Awards,
Franchises, Findings, Explore, Errors, Legal, GmUi, and Arcade expansions).
Human language review is still pending for all non-English catalogs. Intentional
English tokens (metric codes, brand names, short cognates) are listed in
`src/i18n/allowlist.ts`.

Route-by-route coverage, payload measurements, and verification evidence:
see [i18n-coverage.md](./i18n-coverage.md).

## How locale is chosen

1. If `DRBL_FORCE_LOCALE` is set to an implemented locale → that locale (deploy override).
2. Else if `DRBL_LOCALE` cookie is an implemented locale → that locale.
3. Else if cookie is `en-XA` and `NODE_ENV !== "production"` → pseudolocale.
4. Else (`auto`, missing, invalid, or `en-XA` in production) → negotiate `Accept-Language`.
5. Runtime merge fills any missing keys from English. Catalog validation runs **before** merge.

Cookie values: `auto` | `en` | `es` | `fr` | `de` | `pt-BR` | `ko` | `ja` | `zh-Hans` | `zh-Hant`.

## Rollback and English-only

| Action | Effect |
|--------|--------|
| Clear `DRBL_LOCALE` / set Settings → Automatic | Restores **automatic** detection from `Accept-Language`. Does **not** force English. |
| Settings → English (`DRBL_LOCALE=en`) | Forces English for that browser. |
| `DRBL_FORCE_LOCALE=en` (Next `process.env` and Worker env) | Deploy-wide English-only; ignores cookie and Accept-Language. |
| Unset `DRBL_FORCE_LOCALE` | Returns to cookie / Accept-Language resolution. |

Do **not** delete `src/proxy.ts` to “turn off i18n”. It also merges `Vary` for
locale-sensitive HTML. Removing it risks shared caches mixing languages.

Safe rollback steps:

```bash
# Application-level English-only (recommended for emergency rollback)
# Next.js / OpenNext process env:
export DRBL_FORCE_LOCALE=en

# Cloudflare Worker secret/var (PAGE_CACHE keys honor the same name):
# wrangler secret put DRBL_FORCE_LOCALE   # value: en
# or set in dashboard → Variables
```

Per-user English without a deploy: Settings → English.

## Pseudolocale (`en-XA`)

- Stress-tests long labels: wraps text in `【…】···` while preserving `{placeholders}`.
- Set cookie `DRBL_LOCALE=en-XA` in development only.
- Production rejects `en-XA` and falls through to Accept-Language / Automatic.
- Worker cache keys treat `en-XA` as its own bucket so it never poisons English HTML.

## Architecture notes

| Piece | Role |
|-------|------|
| `src/proxy.ts` | Attempts `Vary: Cookie, Accept-Language` + `x-drbl-locale-vary` |
| `next.config.ts` `headers` | Declares Vary including Cookie, Accept-Language, and RSC fields |

**Caching caveat:** Next.js App Router can overwrite application `Vary` with RSC
router fields (upstream issue). Do not rely on CDN Vary alone. This project’s
Worker `PAGE_CACHE` keys include the resolved locale segment
(`page:{version}:{locale}:{path}`) so HTML is not shared across languages.
Deployed Cloudflare HIT/MISS behavior was not verified from this workspace.
| `src/i18n/request.ts` | Resolves locale + loads merged messages |
| `src/i18n/messages.ts` | Dynamic import + English deep-merge fallback |
| `src/i18n/client-messages.ts` | Namespaces shipped to `NextIntlClientProvider` |
| `src/i18n/locale-cache-key.ts` | Locale segment for Worker `PAGE_CACHE` keys |
| `worker.ts` | HTML KV cache keyed by `page:{version}:{locale}:{path}?{query}` |

Installed at last audit: Next.js `16.3.0`, next-intl `4.14.9`,
`@opennextjs/cloudflare` `1.20.2`, wrangler `4.125.0`. OpenNext incremental
cache R2 override is commented out in `open-next.config.ts`.

## Content classes

| Class | Localization approach |
|-------|------------------------|
| Interface chrome (nav, filters, buttons, empty/error) | `messages/*.json` |
| Site-authored educational/editorial UI chrome | Message catalogs |
| Long Learn article bodies | `src/content/learn/locales/<locale>/topics/<slug>.json` via `load-localized.ts`; English fallback. See that folder's README |
| Database prose / provider blurbs | Leave source language; do not machine-translate live |
| User-generated content | Leave as authored |
| Player/team names, metric IDs, formulas, numbers | Never translate |

## Validation

```bash
npm run test:i18n
```

Checks key parity (nested), interpolation variable parity, empty strings,
accidental English (allowlist), ICU plural presence when English uses plural,
locale matching, merge fallback, force-locale precedence, and cache-key isolation.

## Adding keys

Write the English keys (and any translations you have) in an overlay under
`scripts/i18n-overlays/`, then run:

```bash
node scripts/sync-i18n-new-keys.mjs scripts/i18n-overlays/<file>.json
npm run test:i18n
```

Locales without a translation get the English text and the key is listed in
`src/i18n/pending-translation.ts` so the accidental-English check passes. Remove
a key from that list once every locale has a real translation.

## Reproduction commands

```bash
# Unit / catalog gates
npm run test:i18n
npx tsc --noEmit -p .

# Dev (reuse :3000 if already up)
npm run dev

# Locale smoke (cookie)
curl -s -H 'Cookie: DRBL_LOCALE=de' http://localhost:3000/ | rg -o 'lang="[^"]+"' | head -1
curl -s -H 'Cookie: DRBL_LOCALE=ko' http://localhost:3000/standings | rg -o 'lang="[^"]+"' | head -1
curl -s -H 'Accept-Language: ja' http://localhost:3000/ | rg -o 'lang="[^"]+"' | head -1
# Production must ignore en-XA:
NODE_ENV=production # (or prod build) Cookie DRBL_LOCALE=en-XA → not en-XA

# Force English
DRBL_FORCE_LOCALE=en npm run dev

# Payload size (catalog files)
wc -c messages/*.json

# OpenNext local preview (Worker runtime) — heavy; do not confuse with next start
# npm run preview   # see package.json; builds runtime snapshots then opennext
```

Deployed Cloudflare cache isolation beyond local Worker code review requires
access to the live Worker/KV dashboard; this repo documents the intended key
shape but cannot claim edge HIT/MISS verification without a deployed check.
